# 软件安装与机器整理

## 1. 安装前判断

1. 先运行本 Skill 的 inspect，再用 `command -v python3 curl ssh wg doctl` 检查已有工具。只补当前分支缺少的组件；复用当前正常运行的 VPN 客户端，不叠装多个 TUN 接管程序。
2. 系统和 CPU：macOS/Linux 用 `uname -s`、`uname -m`；Windows 用系统“关于”的系统类型。arm64/aarch64 与 x86_64/amd64 不能混装，不能把 macOS 的 DMG 给 Windows。
3. 发行软件只能使用其正式安装渠道。下载文件到本轮私密缓存，限制单个安装包 250 MiB、总本轮下载 500 MiB；需要更大时先查所选包是否包含无关组件，不悄悄全量下载源码和历史版本。
4. 有包管理器就复用其签名/校验机制；独立下载时核对发布者、版本、系统架构及发布包校验和/系统签名。仅自己计算 SHA256 只能标识文件，不能证明发布者；没有验证依据就不执行不明包。

## 2. macOS

1. 有 Homebrew 时安装当前需要的工具，不升级整机已有软件：

```sh
brew install python wireguard-tools doctl
```

2. 没有 VPN 客户端且已获安装许可时：`brew install --cask clash-verge-rev`。已有其他正常客户端时不执行此命令，按本机手册选择兼容分支。
3. 没有 Homebrew 时，不为了安装一个组件而擅自加全局包管理器。使用现有系统 Python；缺少时从 Python 正式下载页面选择当前系统支持的 macOS installer，核对安装包签名，通过系统安装器完成。WireGuard 可使用系统应用商店的正式 App 生成设备密钥；供应商操作使用控制台分支，避免必须安装 doctl。
4. 安装 App 后首次从“应用程序”打开；系统“隐私与安全性”或 VPN 配置确认由本人完成。不要执行移除隔离标记、关闭 Gatekeeper 或禁用 SIP 的命令。
5. 在客户端设置安装其服务模式，启用 TUN 时本人允许网络扩展/VPN。权限被拒绝先说明需要在哪个系统界面允许，不关闭宿主权限检查。
6. 读回应用版本、内核版本和服务状态。存在重复的旧客户端自启动时先确认用途，只在系统“登录项与扩展”停用本轮已确认冲突的那一个，不删除其他产品服务。

## 3. Ubuntu/Linux

1. Ubuntu 客户端先用 `sudo apt-get update`，再按缺失项安装 `python3 curl openssh-client wireguard-tools`。无 sudo 继续只读及用户级配置，不改 sudoers。
2. 服务器仅用服务器手册的包集合；不安装桌面客户端、浏览器或管理面板。
3. 桌面 VPN 客户端使用系统支持的软件包：Debian/Ubuntu 选择 amd64 或 arm64 的 deb，Fedora 类选择对应 rpm；核对发布者和包摘要后用原生包管理器安装，不运行随机 shell 安装器。
4. 获准安装的 deb 先放缓存，运行 `sudo apt install '<该包的实际路径>'`；RPM 使用发行版原生 dnf。先读安装器将要修改的集合，不盲加 `--force` 或关闭签名检查。
5. 无 GUI 的 Linux 可复用现有 Mihomo 服务及配置，不要求装桌面；仅创建本轮需要的用户/系统服务，不能替换其他工作负载的守护进程。

## 4. Windows

1. 复用已有 Python 3、OpenSSH 和 curl。Python 命令用 `py -3` 或已验证的 python；不要仅凭命令存在而假定不是应用商店占位入口，运行 `--version` 读回。
2. 在系统应用管理或正式产品分发页面选择对应架构的安装器；核对“数字签名”里的实际发布者和有效状态。无法核验时不运行未知 exe，不关闭 SmartScreen。
3. VPN 客户端以其正式安装器安装网络服务；出现 UAC、驱动/VPN 授权由本人确认。安装后查看系统网卡和客户端服务状态，不手工删除未知虚拟网卡。
4. 文件写入和恢复使用宿主能验证 ACL 的系统机制。不要对本机含私钥的文件套 POSIX chmod 后声称权限已经安全；本仓 Python 文件事务和配置输出明确拒绝 Windows 写入。
5. 如果当前宿主只能运行本仓只读工具，先完成 inspect/hash/probe，其余标明具体系统接点，不假称整套 Windows 配置已验证。

## 5. 精确清理旧设置

1. 先判定故障是否确实来自旧设置。列出相关应用、配置项、进程及自启动入口，只处理与本轮目标冲突的项；“检查到文件存在”不等于该文件该删除。
2. 清理 shell 代理时读取实际定义文件，保存原散列和对应行；只删除/修改已证实过期的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 或产品连接项，保留其他用途。生成替换文件，经 shell 语法检查后用 apply-files 写入。
3. 验证新进程环境；现有进程不自动刷新。选择自然边界重启目标客户端，不停止提供当前控制通道的 AI。
4. 若某个旧 VPN 服务抢占网络，先在其原生界面关闭接管/自启动，核对路由恢复，再启动目标客户端。不能同时启用两个默认路由接管器来碰运气。
5. 缓存只回收本轮生成且用途结束的安装包、下载临时文件、校验输出和冗余渲染目录；逐个核对归属，不用应用名模糊匹配全盘删除。系统临时目录、Home、共享缓存和其他项目不清空。
6. 不自动删除账号凭据、Keychain、浏览器会话、设备身份、源码和历史。用户单独明确要求清除某项时，列出准确对象、对登录/恢复的影响及恢复入口，沿该授权处理；不把它当默认“防封清理”。
7. 结束前关闭自己临时启动的测试窗口、预览服务和辅助进程，按 PID 和身份核对，不批量 kill 同名应用。正常 VPN 服务及用户要求持续运行的进程保持运行。
