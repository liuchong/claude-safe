# 电脑准备与文件操作

## 1. 建立操作范围

1. 确认是只读检查还是配置；默认对象是指定的当前电脑。记录实际需要的网站、Desktop、Code、API，不扩大到未要求的设备。
2. 运行 `python3 -B scripts/claude_safe.py inspect`。读取系统、代理开关、可执行文件及相关配置存在性；输出不含配置值。另用客户端“关于”或 `--version` 取得实际版本。
3. 确认当前 AI 的控制进程和网络。若准备修改的是唯一控制网络，先准备原客户端恢复或独立 SSH 通道；没有恢复通道就不做断线演练。
4. 只读取本轮需要的配置字段，找到正在加载的配置、持久合并/覆写入口、相关端口和管理接口。不复制整个 Home、Keychain、浏览器资料或会话目录。
5. 沿用已有预算和安装权限。仍缺少时一次说明：哪台机器、哪种产品、有无线路、新资源费用上限和续费选择、能否管理员操作。不要让用户替你做可自行判断的技术选型。
6. 在宿主已有私密任务缓存建立本轮目录，权限 0700。无宿主规定时使用 `~/AI/caches/claude-safe/<唯一任务名>/`。真实参数、恢复材料和安装包不放本仓。

## 2. 分清故障

1. 查看错误类别和时间，区分 DNS/连接失败、HTTP 服务响应、登录过期、额度不足、付款失败和账号停用；只保留错误类别和不含账号信息的错误码。
2. 额度不足按实际刷新或订阅处理；停用走账号内支持入口，不删设备 ID、不轮换账号、不换 IP 冒充恢复。
3. 核实本人及所选产品在实际使用地区的资格。美国出口不会改变居住地、身份或资格；不满足时停止开通分支，继续其他合法可用部分。

## 3. 准备电脑

1. 检查系统时间同步：macOS 查看“日期与时间”，Linux 用 `timedatectl status`，Windows 查看系统时间设置。时区默认保留；明确要求时改到真实使用时区，再读回。
2. 检查磁盘余量和系统版本，只装系统支持的官方软件。已有正常客户端不重装，不为了“干净”删除所有数据。
3. 查看 shell、启动项和应用中的代理及服务连接设置。非空不等于错误；先确认用途，只替换冲突的精确项，把原值保存到受限恢复文件。
4. shell 环境通常只影响后来启动的子进程；桌面应用可能不继承它。分别确认配置来源、进程启动时环境及实际采用。
5. 浏览器复用本人资料或独立工作资料，保留密码管理和 MFA。不随机伪装指纹、改硬件编号、导入他人 Cookie 或清除全部登录。
6. 手机、邮箱和支付恢复方式应长期可控，不为匹配出口编造身份、地址、电话号码或时区。

## 4. 选择网络分支

| 现场 | 动作 |
| --- | --- |
| 已有固定可用节点 | 不购买，按本机手册接入和验收 |
| 已有授权 VPS | 查系统、服务、SSH 和 IP；在用机不能照新机步骤覆盖防火墙 |
| 没有线路但有预算及购买授权 | 按服务器手册购买一台，不增加无关服务 |
| 无预算、凭据或 UDP 不通 | 完成无依赖准备，记录具体阻塞，不循环换机购买 |

## 5. 精确写入与恢复

1. 对每个目标运行 `python3 -B scripts/claude_safe.py hash '<目标>'`；已有文件填真实 SHA256，不存在才填 null。
2. 生成最小改动的新文件，用目标软件原生命令验证完整配置。事务工具不理解 YAML、DNS 或服务语义。
3. 在私密目录创建计划；相对路径以计划目录解析，authorized_files 与 files 目标集合必须完全相等。

```json
{
  "schema_version": 1,
  "authorized_files": ["./target-config.json"],
  "files": [{
    "path": "./target-config.json",
    "before_sha256": null,
    "content_file": "./validated-config.json"
  }]
}
```

4. 执行 `python3 -B scripts/claude_safe.py apply-files --plan '<计划>' --state-dir '<受限恢复目录>'`。最多 16 个文件，单文件 2 MiB，总新旧内容 8 MiB；全部预检后才替换。不用于远端文件或需要提权的系统目录。
5. 记录 transaction，调用客户端加载，再验收。写入成功不代表生效。
6. 失败用 `python3 -B scripts/claude_safe.py rollback --state-dir '<原目录>' --transaction '<原ID>'`，再恢复客户端加载。现场已被其他操作改动时拒绝覆盖，说明冲突。
7. 逐文件原子替换不是跨文件断电原子事务；中断后查状态和散列再续接。写锁被占用不删除、不抢占。
8. 备份和清单 0600，恢复目录 0700。Windows 使用经核验 ACL 的原生机制，不使用此 POSIX 写入适配。成功后回收无用副本，保留必要受限恢复入口。
